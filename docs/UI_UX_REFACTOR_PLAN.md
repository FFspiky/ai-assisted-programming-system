# 智练 CodeLab 前端重构方案旧稿

> 本稿已停用。当前方案见 [前端视觉精修方案](UI_UX_VISUAL_REFINEMENT.md)。首页保留产品展示定位，全站以现有骨架上的视觉精修为主；本稿中的首页工作台、题库全列表化和练习页强制双栏不再作为实施要求。

2026 年 10 月 13 日 · 设计提案

建议将智练 CodeLab 重构为一个专注的编程学习工作台，围绕「选题 → 编写 → 提交 → 查看执行证据 → 主动求助 → 修改与复测」组织界面。保留深色蓝系、Python/C++ 练习与达菲郁的辨识度，通过统一视觉规范、提高编辑区可见性和明确帮助边界改善体验。

本方案覆盖首页、题库、练习、学习分析、个人页、认证和管理页。首轮实施以练习主流程为先，技术上沿用 Flask/Jinja 和原生 JavaScript，逐页迁移；UI 重构不以更换前端框架为前提。文内尺寸、阶段工期和体验目标均为建议值。

## 1 现状与重构依据

设计建议需结合当前模板、样式和接口验证，不作为功能已完成的依据。

| 现状及位置 | 对使用的影响 | 重构决策 |
| --- | --- | --- |
| `templates/index.html` 首屏含产品标题、模拟编辑器外观、功能介绍，后续为团队展示 | 已登录学习者缺少明确的继续入口；首页编辑器外观不代表能直接写代码 | 登录后显示学习工作台；访客显示简短介绍和进入题库；团队信息放低优先级位置 |
| `templates/problem_selector.html` 以题目卡片展示，当前脚本无搜索和筛选 | 扩展题量后查找和比较成本升高 | 桌面用紧凑列表，提供题号/标题搜索、难度和通过状态筛选；手机用列表行重排 |
| `templates/practice.html` 题面、编辑器、输入、输出纵向排列；实际浏览器首屏无法同时看到结果区 | 做题时反复上下滚动，证据与代码难以对应 | 桌面题面与代码并列，结果固定在编辑器下方；窄屏用题目/代码/结果页签 |
| AI 优化、运行、提交位于同一工具条，诊断、聊天、补全分散在不同入口 | 帮助程度难以形成一致预期 | 保留提交为主操作，运行为次操作；诊断和分级帮助靠近提交结果；通用聊天仍为手动入口 |
| `templates/learn-analytics.html` 将带 `inert` 的 20 题问卷放在概览之前，界面提示暂停开放 | 未开放功能占据首屏，真实学习记录后置 | 概览和最近练习前置；问卷从主流程移走，功能接通后再作为可选学习设置 |
| index/practice/analytics 样式分别维护全局选择器和颜色变量，题库、认证与管理页含内联样式；个人页依赖首页样式 | 同一导航、按钮和状态出现不同外观，修改容易串页 | 建立共享布局、语义 token 和基础组件，页面样式限域 |
| `static/js/practice.js` 约 1029 行，包含编辑、补全、执行、聊天及窗口几何；`evidence.js` 同时管理草稿与结果 | 布局改动容易破坏业务耦合 | 先保持 DOM/API 契约，再按职责拆分；组件抽取与功能新增分批进行 |

已有项目反馈要求帮助靠近结果、保留角色、不恢复独立诊断右栏和演示宣传入口，见 [F1 说明](EVIDENCE_DEMO.md) 与 [参赛实施方案](AIGC_COMPETITION_ROADMAP.md)。本次全站重构提案扩大了视觉整理范围，延续这些具体交互约束。

## 2 信息架构与页面职责

主导航固定为「学习首页 / 题库 / 学习分析」，头像进入「个人主页 / 账号设置」。练习是题库下的工作空间，不增加第四个重复导航项；管理入口仅向管理员展示。

| 页面 | 核心问题 | 首屏内容与主操作 | 保留路径 |
| --- | --- | --- | --- |
| 学习首页 | 我接下来做什么 | 最近练习与继续按钮、累计通过题数、最近提交；新用户改为选择第一题 | `/index.html` |
| 题库 | 我想找哪道题 | 搜索、难度、通过状态、题目列表；主操作为打开题目 | `/problem_selector.html` |
| 练习 | 代码为什么失败，下一步怎么改 | 题面、编辑器、提交结果、按需帮助 | `/practice.html?problem=…` |
| 学习分析 | 我练了什么，下一步可做什么 | 去重通过题数、提交通过率、练习时长、趋势与最近记录；主动查看 AI 建议 | `/learn-analytics.html` |
| 个人主页 | 我的资料与练习档案 | 头像、简介、活动日历、提交记录；资料/安全用分区导航 | `/profile.html` |
| 登录与注册 | 如何开始并回到刚才的任务 | 简洁表单、字段错误、显示密码、登录后回跳 | `/login.html`、`/register.html` |
| 管理页 | 如何准确维护题目 | 题目列表、编辑、导入预检、公开/隐藏用例设置 | 沿用当前路由 |

首页只展示少量近期内容；完整趋势归学习分析，完整个人档案归个人主页。排行榜下沉到学习分析的次级区域。暂不添加课程商城、社交、成就系统、自动推荐画像等新主线。

### 学习首页的两种状态

- **访客**：一句产品说明、浏览题库、登录入口。浏览题面无需先填问卷；运行/提交沿用登录要求。首页不展示伪造的个人学习统计。
- **已登录**：优先恢复同一账号在本浏览器最近练习；没有本地记录则显示最近提交；均无记录则引导选第一题。跨设备草稿同步属于新增能力，不能由本地存储暗示已经支持。

## 3 视觉系统

方向：低装饰、适中密度、清楚的代码与证据层级。使用纯色底、细边界、有限圆角；品牌蓝负责操作与选中态，绿/橙/红只负责状态。取消大面积光晕、渐变标题和多色发光按钮。

### 颜色 token

深色作为首轮主要设计与验收对象，同时定义浅色映射，最终提供「跟随系统 / 深色 / 浅色」。主题偏好保存在本机，独立于账号数据。

| 语义 token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `--cl-bg` | `#0F141C` | `#F4F6FA` | 页面背景 |
| `--cl-surface` | `#171E29` | `#FFFFFF` | 面板 |
| `--cl-raised` | `#202938` | `#EAF0F8` | 悬停、二级分区 |
| `--cl-text` | `#EDF2F8` | `#182234` | 主文字 |
| `--cl-muted` | `#AAB6C8` | `#526176` | 次级文字 |
| `--cl-border` | `#354257` | `#CAD3E0` | 分隔线；不可单独承担控件可见性 |
| `--cl-control-border` | `#75859C` | `#78879C` | 输入框等必要边界 |
| `--cl-primary` | `#4361EE` | `#4361EE` | 主要按钮，文字使用白色 |
| `--cl-link` | `#9BAEFF` | `#304CCC` | 文字链接、选中标签 |
| `--cl-success` | `#69C79A` | `#176D46` | 通过，搭配文字与图标 |
| `--cl-warning` | `#F1C36B` | `#865500` | 过期证据、未验证 |
| `--cl-danger` | `#FF9CA4` | `#B42335` | 错误、表单校验 |

普通文字对比度目标不低于 4.5:1，必要控件边界与焦点不依赖微弱分隔线。分别检查实际浅深背景组合，不把 token 表本身视为无障碍验收。参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### 排版与尺寸

- 正文优先系统中文无衬线：`system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`；代码沿用 Source Code Pro，回退 `ui-monospace, SFMono-Regular, Consolas, monospace`。中文阅读不依赖 Google Fonts 成功加载。
- 字号层级：页面标题 28/36px，区块标题 18/26px，正文 16/26px，控件 14/20px，次要标签 12/18px；移动端输入文字至少 16px。
- 间距：4、8、12、16、24、32、48px。按钮高 36px，主要操作 40px；触屏有效热区优先 44×44 CSS px。后者是产品目标，WCAG 2.2 AA 的一般最低目标为 24×24 CSS px 或满足相应例外，见 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
- 圆角：按钮/输入 8px，面板 12px；状态标签才使用胶囊。阴影只用于弹层，普通卡片靠边界分层。
- 普通页面内容最大宽 1200px，左右留白 24–40px；练习页利用可用宽度，最大建议 1680px，外边距 16px。顶部导航压缩到约 64px。
- 图标统一单一描边风格。首轮可封装现有 Font Awesome 以降低变更量，后续整体切换本地 SVG；不在同一导航层混用 emoji 和多套图标。
- hover 约 120ms，面板开合约 180ms；按 `prefers-reduced-motion` 关闭非必要位移和循环动画。流式输出不强制滚动，用户停留在旧消息时显示“有新内容”。

## 4 练习工作空间

### 桌面布局

```text
┌ 智练 CodeLab   学习首页 / 题库 / 学习分析             头像 ┐
│ 返回题库    整数求和 · 简单                   上一题 / 下一题 │
├─────────────────┬──────────────────────────────────────┤
│ 题目              │ Python ▼    运行代码       提交解答     │
│ 描述、约束         │ 代码编辑器                              │
│ 输入 / 输出        │                                        │
│ 示例               ├──────────────────────────────────────┤
│                   │ 测试输入 / 运行输出 / 提交结果            │
│                   │ 用例状态 + 预期与实际                     │
│                   │ 获取帮助 → 概念 / 定位 / 局部 / 完整参考   │
│                   │ 按需展开修改对比、复测与过程               │
└─────────────────┴──────────────────────────────────────┘
```

≥1100px 使用约 34%/66% 的两栏，题面下限 300px、代码区下限 560px；768–1099px 切换「题目 / 代码与结果」，避免硬挤双栏；<768px 使用「题目 / 代码 / 结果」三个明确页签，提交完成后提示切换到结果。桌面如增加拖动分隔条，同时提供恢复默认和键盘调整，不依赖拖拽。

首次进入保持题面可见；编辑时收起次要说明。代码区与结果区允许桌面分区滚动，但避免整个页面、编辑器和弹层同时形成不必要的多层滚动。手机以页面自然滚动为主，代码编辑器按需内部滚动；底部固定操作栏需要给内容和软键盘留出空间。

### 操作层级与帮助

1. **提交解答**是唯一高强调按钮；**运行代码**为描边次按钮，区分自定义输入与题目用例判题。
2. 语言、自动补全、草稿状态属于编辑器局部控件。第一批保留现有 textarea 与补全行为，新增可见标签和焦点；不要同时更换编辑器引擎与布局。
3. AI 优化移到低强调的辅助入口，不能绕过学习模式。普通聊天保持“主动附带当前练习”的选择，默认不静默收集上下文。
4. 分级帮助位于提交结果之后。概念线索、定位与解释、局部修改、完整参考均有清楚入口，选择不自动升级；完整参考显式说明会展示较完整答案。
5. 学习/辅助模式由服务端返回并核验；前端只呈现策略。学习模式下补全默认关闭，主动开启应说明并记录辅助状态变化。该行为需与在研后端及旧默认开启行为一起联调。
6. 点击证据定位保存的提交快照。编辑器已变化时先注明“当前代码已修改，以下结果来自上次提交”，不能把旧行号当作当前编辑器行号。

### 必须设计的状态

| 状态 | 界面文案或行为 |
| --- | --- |
| 尚未提交 | “提交后可查看测试结果”；不展示示例诊断充当真实结果 |
| 正在执行 | 按钮显示执行中，阻止重复提交，保持题面与代码可读；不使用虚构百分比 |
| 首个用例失败 | 展示失败用例和未执行数量；未执行用例不标为失败 |
| 全部通过 | “本次提交通过当前 N 个用例”；不自动宣称已掌握 |
| 仅隐藏用例失败 | 只展示允许公开的状态；缺乏公开证据时说明无法准确定位 |
| 帮助生成中 | 支持停止等待；中断不承诺服务端请求已撤销 |
| 网络失败或超时 | 就地提示重试，保留代码、输入、既有证据；区分执行失败和题目答案错误 |
| 代码已变更 | 旧证据保持可回看，但标为上次提交；需要新提交确认当前结果 |
| 建议尚未运行 | 明确“待验证”；采纳不直接改成通过 |
| 登录失效 | 先保存草稿，再引导登录并返回同一题；保留账号隔离 |
| 本地存储不可用 | 提示草稿未能保存；编辑和手动复制仍可继续 |

### 达菲郁与后续复盘

保留当前角色素材、署名、手动打开聊天、拖动/缩放/最大化和减少动效设置。角色默认停靠在不遮挡运行、提交与证据的位置；增加清楚的收起/恢复入口。聊天窗口是按需浮层，不占固定第三栏。

局部 Diff、采纳/拒绝、撤销、关联复测、历史时间线属于后续功能，需要后端事件与版本关系支持。达到前置条件后在结果区按需展开；应用前核对建议基于的代码版本，用户已继续编辑时不得用旧快照覆盖。首轮可以完成样式约定，但不以可点击的空按钮冒充已接通。

## 5 其余页面的具体改造

### 题库

桌面列为「题目 / 难度 / 状态 / 开始」，题号作为标题的次级信息。首轮搜索匹配题号和标题，难度与通过状态直接使用 `/api/problems` 字段；“已尝试未通过”需结合用户提交，不能由 `accepted: false` 推断。不存在知识点标签字段时不先画标签筛选。

筛选值写入 URL，返回题库时恢复过滤和滚动位置。第一批可在现有全量题库结果上本地过滤、分页；题库扩大或响应明显变慢时再增加服务端分页。零结果显示清除筛选操作；接口错误显示重试；访客状态写“登录后记录进度”。

### 学习分析

首屏三个指标固定为去重通过题数、提交通过率、累计练习时长。统计文字写明“累计”，不在只提供累计字段时放“近 7 天”选择器。

活动趋势可复用 `/api/profile` 的每日提交计数，近 7/30 天仅过滤这项趋势；语言分布、难度分布与最近提交沿用其真实口径。先做趋势、分类条形和记录表，不添加无数据依据的能力雷达或掌握度分数。

AI 建议放在真实记录之后，显示所依据的记录范围与更新时间；无提交时引导先完成练习。建议改为用户主动生成/更新，避免每次打开页面都自动触发模型请求；已有缓存可直接阅读。不得以“刷新”暗示用户已获得新的执行证据。

### 个人、认证与管理

个人页沿用现有资料、练习档案、设置、安全分区，统一共享导航与视觉，不再次复制学习分析的全部内容。头像上传保留真实格式/大小限制，错误就地显示，修改密码后的重新登录提示保持明确。

登录/注册与工作台共用 token，输入有可见 label、自动填充属性、密码可见性开关和明确错误；允许粘贴及密码管理器。保留安全的 `next` 回跳与访客草稿转交。

管理页使用同一组件体系的高密度版本；导入前先展示解析结果、错误行和数量，公开/隐藏测试用例用文字清楚区分。不得因美化表格而隐藏校验错误或改变权限校验。

## 6 组件与工程迁移

建议目录是目标结构，不表示文件已创建：

```text
templates/
  base.html                   共享 head、主题与导航
  partials/                   nav、user-menu、feedback
  components/                 button、empty-state、result-summary
  practice.html               装配题面、编辑器、结果、聊天
static/css/
  tokens.css                  颜色、排版、间距与主题
  base.css                    重置、焦点、排版、布局基础
  components.css              按钮、输入、页签、状态、弹层
  pages/                      每页限域样式
static/js/
  core/                       api、theme、feedback
  practice/                   page、editor、drafts、runner、evidence、help、chat
  pages/                      dashboard、problems、analytics、profile
```

组件至少覆盖 AppHeader、PageHeader、Button、Input、Tabs、ProblemRow、EditorToolbar、SubmissionSummary、CaseEvidence、HelpSelector、EmptyState、InlineError、Dialog。统一定义默认、hover、focus、pressed、disabled、loading 状态；旧脚本适配完成之前保留 `codeInput`、`runBtn`、`submitBtn`、`submissionResults`、`diagnoseBtn` 等现有 ID。

推荐迁移顺序：token → 共享模板 → 页面布局 → 状态与反馈组件 → JavaScript 职责拆分。保留 `UserSession.csrfFetch`、`SafeContent` 安全渲染、草稿按稳定用户 ID/题目/语言隔离以及请求过期保护。布局迁移不修改接口字段、存储键和 SSE 解析约定。草稿格式如必须改变，要有旧格式读取与迁移策略。

原生 ES modules 可按页面逐步引入，先隔离模块间依赖；不要在一次提交中同时把全部全局脚本改为模块。若后续决定采用 React/Vue，应另立有业务理由的迁移任务，本方案无此必要依赖。

### 接口与功能成熟度

| 区域 | 可复用来源 | 本轮设计的边界 |
| --- | --- | --- |
| 题库/题面 | `GET /api/problems`、`GET /api/problems/<id>` | 无题目标签或全站题目通过率字段 |
| 运行/判题 | `POST /api/run-code`、`POST /api/check-solution` | 保持结果与提交快照绑定 |
| 最近结果/诊断 | `GET /api/problems/<id>/latest-submission`、`POST /api/submissions/<id>/diagnosis` | 保留证据不足、隐藏用例、超时与取消语义 |
| 个人与概览 | `GET /api/profile`、`GET /api/learning_overview` | 统一累计口径；日期趋势来自真实 activity |
| 学习建议 | `GET /api/ai_learning_analysis_stream` | 可用性不等于能力测评有效性 |
| 分级帮助 | 后端已有 `/api/help-settings`、`/api/submissions/<id>/help`、`/api/help/<id>/shown`，并已增加聊天与代码工具的策略约束 | 前端仍未接入模式与帮助选择控件，尚不能标记整条流程已验收 |
| 修改复盘 | 当前未发现完整 Diff/采纳/撤销/关联复测前端链路 | 后续需数据模型、API 与版本一致性处理 |

页面切换和组件卸载需终止旧监听/等待，重复进入不能重复绑定提交或 SSE 回调。会话切换要清理上个账号的展示与缓存引用。

## 7 实施批次与估算

以下为熟悉项目的一名前端开发者的粗略投入，不包含后端新功能、内容录入或多轮视觉返工。阶段可独立交付和回退，日期在实际排期时确定。

| 批次 | 预计投入 | 交付与退出条件 |
| --- | --- | --- |
| P0 设计与基础 | 1–2 人日 | 确认主要布局、token、共享导航与组件样例；深浅主题关键组合可读 |
| P1 练习主流程 | 3–4 人日 | 两栏/窄屏结构、清楚的运行与提交、证据及过期态；现有草稿、聊天、补全不回退 |
| P2 题库与学习首页 | 2–3 人日 | 搜索筛选、列表、继续练习、访客/空数据状态 |
| P3 分析与账号页面 | 2–3 人日 | 统计口径一致、问卷退居次级、统一个人/认证/管理页 |
| P4 帮助与复盘深化 | 依后端联调另估 | 分级帮助、模式联动、Diff 和复测链路按成熟度接入 |

P0–P3 约 8–12 人日。若先服务比赛演示，完成 P0/P1 及题库必要入口即可形成一版可演示的主流程，再扩展其他页面。

实施时按页面保留旧模板回退路径或独立提交，不在布局批次删除旧草稿、修改数据库或覆盖并行中的帮助后端工作。待该页验证后才删除旧样式；`templates/样题1.html` 等历史文件先确认引用，再决定归档。

## 8 验收与体验验证

### 必要回归

- 页面尺寸：1440×900、1280×800、1024×768、768×1024、390×844，以及 320px 窄屏；核对页面无横向溢出、弹层不盖住关键操作、200% 缩放仍可使用。
- 主流程：访客选题 → 输入代码 → 登录回跳 → 草稿恢复 → 运行 → 错误提交 → 查看证据 → 修改 → 再提交；Python/C++ 均覆盖。
- 数据一致性：修改代码不改变旧证据；刷新恢复同一提交；切语言和切账号不串草稿；AI 返回晚于用户编辑时不会自动覆盖。
- 失败路径：离线、401、429、执行器不可用、AI 超时、取消等待、公开证据不足、本地存储不可用；每条路径都保留用户可恢复工作。
- 键盘：导航、页签、编辑器退出、运行、帮助、聊天开合可访问，焦点可见；弹层关闭后返回触发处。状态播报只报阶段变化，不逐 token 打断阅读。
- 功能保留：补全 Tab 接受/Esc 取消、手动附带上下文、聊天停止、窗口恢复、桌宠收起与减少动效。

重用 `tests/smoke/` 中已有页面、证据、个人、聊天、补全和桌宠检查；只增加迁移真正引入的有意义行为检查。UI 方案阶段不运行真实模型或写入个人数据库；实施阶段用独立测试账号/数据库检验。

### 小规模可用性验证

邀请 3–5 位目标学习者依次完成找题、运行、识别失败证据、请求较少帮助、修改再提交。记录找入口所需时间、误点次数、证据与当前代码是否混淆、是否知道如何停止帮助。

目标：从学习首页到最近练习不超过 1 次主操作；筛选状态返回可恢复；使用者能区分运行/提交、事实/疑似原因、旧证据/当前代码。先记录旧版基线，再比较新版；不预先宣称提升百分比或学习成效。
