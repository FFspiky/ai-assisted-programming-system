# 智练 CodeLab AIGC 参赛亮点与演示实施方案

更新日期：2026 年 10 月 12 日。目标赛项：指定命题中的 AIGC 类数字创意作品创作，主方向为 AIGC 智能助手与交互体验设计。

作品建议定位为「智练 CodeLab——让编程错误可解释、学习帮助可控制、人机协作可回看」。开发围绕一条能在几分钟内展示清楚的流程展开：学生提交错误代码，查看真实失败证据，按需获得提示，亲自修改或选择采纳建议，重新判题，回看整个协作过程。

本版将参赛亮点与演示效果放在优先位置。必要修复服务于核心流程，工作台呈现与功能同步完成，验证只保留确认流程可运行、创新确实实现及已知关键问题已修复所需的检查。除下方明确完成的项目外，文中的功能、画面和案例仍为实施目标。

**一、重新评估后的取舍**

现有系统具备题库、Python/C++ 运行判题、提交记录、AI 聊天、补全、优化和学习分析，可直接复用。主要机会是把这些能力组织成有辨识度的教学交互，并让评委看见学生和 AI 分别做了什么。

原方案的主要问题是前置工作过重：要求先完成全平台统计与计时治理，再制作较多核心题和评测集，核心工作台的展示却排在后面。本版调整如下。

| 原安排 | 本版安排 | 目的 |
| --- | --- | --- |
| 先完成全部 R1—R6，再开发亮点 | 核心执行、渲染、判题等必要修复先处理或并行，其余平台治理后置 | 尽早得到第一条真实可运行的演示流程 |
| 工作台视觉与交互放在 P2 | 提升到 P1，与三项创新同时实现 | 每完成一项能力，就形成评委能看懂的画面 |
| 至少整理 12 道核心题 | 3 道演示题和 3 个未用于调提示的变式案例 | 覆盖主流程及基本变化，避免扩题库占用时间 |
| 30 例评测、三组对照和 80% 正确率门槛 | 6 个代表案例逐项检查；其中 2 例做精简前后对照 | 验证新增能力，不进行缺乏样本支撑的总体效果推断 |
| 6—10 名学生试用作为计划事项 | 有现成参与者时收集简短反馈，不作为交付前置 | 不让招募与实验设计挤占实现时间 |
| 多项模型、性能和成本指标 | 保留真实输入输出、提示动作、修改差异、判题结果与模型版本 | 让证据直接服务创新说明 |

官方对本项目最相关的要求是原创构思、人机协同、人工干预、系统整合、交互设计及贡献可核验；评分中的创新、技术、完成度分别为 25、25、20 分。展示能帮助评委理解这些成果，必须由实际功能支撑。依据见[参赛指南 PDF 第 9—10 页](</Users/a373/Desktop/Study/小学期/说的都队/说的都队 ai辅助编程系统/官方要求/附件1 2026年第十四届全国大学生数字媒体科技作品及创意竞赛参赛指南.pdf>)与[评分标准 PDF 第 4 页](</Users/a373/Desktop/Study/小学期/说的都队/说的都队 ai辅助编程系统/官方要求/附件2 2026年第十四届全国大学生数字媒体科技作品及创意竞赛评分标准及奖项设置.pdf>)。

**二、P1 最高开发优先级的三项亮点**

除下文 P0 的必要保障外，新增开发全部优先投入以下三项。沿用 F1—F3 编号便于后续实施。

| 功能 | 评委看到的具体画面 | 团队需要完成的工作 | 最小完成标准 |
| --- | --- | --- | --- |
| F1 可视化证据诊断 | 失败用例卡展示输入、预期输出与实际输出；点击 AI 诊断，高亮相关代码行与证据 | 将题目、当前代码和真实判题结果关联，生成结构化解释，设计证据卡与行定位交互 | 对真实提交产生解释；引用能打开；运行事实与 AI 疑似原因分别标识 |
| F2 可控的分级提示 | “概念提示 → 定位提示 → 局部修改”逐步展开，学生主动决定帮助程度 | 提示层级与当前提交绑定，统一聊天/补全/优化的学习模式行为 | 三层内容有实际差异；低层不直接输出完整解法；完整参考解法有独立入口并留记录 |
| F3 可视化协作复盘 | 修改前后 Diff、采纳/拒绝动作、复测状态与过程时间线 | 保存代码快照、AI 建议、学生动作及后续提交，串成一页回顾 | 能看到真实修改与结果；建议可撤销；刷新仍可回看；未复测不显示通过 |

**F1 要解决的是“这条解释依据什么”**

复用现有判题结果，保存结构化快照并返回 submission_id。后端依据该 ID 读取当前用户的题目、代码、语言、公开用例和错误信息；模型给出疑似原因、代码行、证据引用及下一步检查。普通输出不自动升级成“事实”，通过状态始终由判题产生。

界面集中显示一条最相关的错误、一张证据卡和一个下一步动作，避免大段聊天掩盖重点。需要时再展开其他已执行用例；遇首错终止后的用例标为未执行。证据 ID 和代码行由服务器校验，诊断的语义正确性通过代表案例检查。

**F2 要解决的是“什么时候帮，帮到什么程度”**

第一层提醒概念和应检查的现象；第二层结合证据定位疑似错误；第三层给局部修改与原因。学生可以升级、暂停或主动查看完整参考解法，无需被迫完成多轮无关问答。

后端记录提示层级。学习模式默认不自动填入整段答案，也不同时输出三个完整优化版本，防止其他入口绕过提示设计。保留原编程辅助能力时，用明确的模式切换区分，并记录系统内的帮助使用。不要把“未点击提示”描述为已经证明学生没有使用外部工具。

**F3 要解决的是“学生实际做了什么，修改是否有效”**

把建议应用改成“查看差异 → 选择采纳或拒绝 → 修改 → 复测”。记录原始代码、提示层级、AI 建议、操作动作、后续代码与实际判题状态。时间线标明哪些改动由系统直接应用、哪些发生在后续编辑中，只描述系统可观察的行为。

建议尚未运行时显示“待验证”；复测后显示“通过当前 N 个用例”或真实失败状态。候选修改必须由现有执行器重新运行，不能依据 AI 的自我评价显示通过。完整回顾页即可支撑截图与演示，JSON/HTML 导出降为可选。

三项亮点共同体现面向编程教学的应用与交互创新。基础代码解释和引导式教学已有成熟产品提供，不能宣称首创；可参照 [GitHub Copilot 文档](https://docs.github.com/en/copilot/how-tos/chat-with-copilot/get-started-with-chat-in-your-ide?tool=webui)和 [Khanmigo](https://www.khanmigo.ai/)说明已有能力。参赛贡献应具体落在本项目的证据组织、提示控制、协作呈现及执行判题集成。

**三、P1 同步完成的演示工作台与案例**

工作台沿用原刷题页的题目、编辑器与运行结果结构，保持已有颜色和按钮风格。诊断嵌入运行结果区，后续提示和复盘也围绕实际操作出现；不另设宣传横幅、独立诊断右栏或面向评委的演示入口。窄屏优先保证内容可读和操作可达。

| 展示设计 | 具体要求 |
| --- | --- |
| 证据关联 | 点击诊断同步定位代码行与用例卡，形成可见的关联；不同类型内容同时使用文字与颜色区分 |
| 提示升级 | 当前层级清楚可见，每次只强调下一步；已读提示可以折叠回看 |
| 修改对比 | 展示局部 Diff，不整页覆盖代码；应用前可查看，应用后可撤销 |
| 运行反馈 | 区分运行中、等待 AI、待复测、通过和失败；等待期间保留已有证据，超时可重试 |
| 演示节奏 | 从选好的题目直接开始，讲解者事先准备输入代码；正常用户可继续上次草稿与提交，不提供载入错误示例按钮 |
| 呈现统一 | 统一字体、间距、代码配色、按钮和状态标签，保证投屏可读；不投入无关动画和全站换肤 |

讲解中的判题和 AI 诊断仍实时执行。网络异常时可切换有明确日期和标识的历史录屏/回放，不把历史输出伪装为实时结果。

准备 3 道有明确来源或团队自编的演示题：循环边界、数组/字符串索引、输入处理。每题保留一个典型错误和可靠参考解法，再各准备一个不同输入或不同错误位置的变式，共 6 个检查案例。变式在提示设计完成后再检查；发现问题如实修复，不能仅替换失败样例。保留原有题库，不要求为全部题目补充标签与教学素材。

每个案例只保留能说明问题的公开用例与必要边界验证。预期答案由参考解法和人工检查确认。隐藏验证用例不进入模型上下文、前端或回顾页；AI 临时生成的测试不能未经核验就成为判题标准。

建议主演示采用 Python；已有 C++ 入口保留时修正语言传递并做一次相关路径检查，不扩展其他语言，也不要求本轮完成 C++ 全套教学案例。未完成的教学能力在说明中标清范围。

**五、P0 只保留支撑核心流程的必要修复**

P0 是相关能力对外演示前必须满足的保障，不要求完成全部平台治理后才能开始工作台与创新设计。界面、题目和提示流程可以与执行修复并行。

| 必修项 | 已发现的问题 | 本轮范围 |
| --- | --- | --- |
| 执行边界与资源回收 | 当前在宿主进程执行；输出先全部捕获再截断 | 使用独立受限执行环境，限制宿主文件、网络、CPU/内存/进程及运行时长；读取输出时限额，任务结束回收。复用简单容器/成熟沙箱，不建设分布式 worker、复杂队列或并发平台 |
| 渲染安全 | AI 回复和优化说明存在原始 HTML 写入 | 对所有保留的 AI 展示入口使用统一安全渲染，文本字段转义；用一个针对事件属性/危险链接的组合样例验证 |
| 判题准确 | 大整数转 float 后可能误判相同 | 整数精确比较，浮点仅在明确启用的题目中使用容差；保留一组针对已知误判的边界回归，不扩展完整 Special Judge |
| AI 请求与语言 | 语言传递错误，部分流式请求缺少可靠超时/分块处理 | 修复当前语言传递；核心诊断与提示使用统一客户端，处理超时、取消、跨块内容、非法输入和迟到响应；核心昂贵接口保留现有限流 |
| 上下文与结果真实性 | 判题结果未完整持久化，模型缺少当前提交上下文 | 保存提交快照并验证归属；模型引用仅限该提交的公开证据；实际判题独立于 AI 输出 |
| 草稿与操作可恢复 | 刷新、切题和异步建议可能干扰编辑 | 按用户/题目/语言保存草稿；应用建议前检查代码版本；核心复盘能刷新恢复 |

独立受限执行环境必须在接受用户输入并执行前生效；不可用时明确停止执行，不退回宿主裸跑。保留针对既有隔离问题和资源限制的最小检查，不以“容器启动成功”代替验收。

其他问题按以下原则处理，不继续前置完整治理：

- 已解题数去重和语言参数属于范围小、会影响展示真实性的修复，顺手完成；不为排行榜建设新积分体系。
- 学习时长防重复、积分并发治理、长期报告持久化和完整问卷能力画像移到 P2。相关指标不作为本次创新效果证据。
- 2026-10-13 已将问卷答案接入学习路径提示词，页面入口仍暂停，完整个性化学习流程待单独验证后再展示。其他已知不可靠的非核心入口同理。
- 非核心模块若经同一公共组件受本轮修改影响，应做受影响检查；不借减少测试跳过已发现的共享组件问题。

**六、P2 后置的功能及最小技术改动**

P2 包括：知识点驱动的下一题推荐、题库高级筛选、全量学习报告、问卷重设计、时长与积分的完整治理、服务成本看板、多语言教学扩展、移动端全面适配和复杂编辑器升级。自训模型、多智能体、语音虚拟人、复杂知识图谱、全站框架迁移继续后置。

本版优先复用 Flask、SQLAlchemy、现有迁移、判题和 AI 客户端。必须的数据改动只有核心过程所需部分：

| 对象 | 本轮需要的信息 |

| 题目与用例 | 演示题标签、来源、判题模式、公开范围；修改题目时能追溯内容版本 |
| 提交 | 代码与语言、结构化判题结果、对应题目/用例快照或版本、上一提交关联 |

**七、最小必要验证与停止规则**

测试只回答三个问题：演示能否顺利完成；三项创新是否实际起作用；本轮触及的已知关键问题是否已修复。共用前述 6 个案例及真实录屏，不另建大规模评测项目。

| 验证组 | 只保留的检查 | 为什么需要 | 最小记录 |
| --- | --- | --- | --- |
| T1 核心流程 | 完成一次“已有账号进入 → 错误提交 → 证据诊断 → 逐级提示 → 修改/撤销 → 复测 → 刷新回顾”；其余演示题只查相应差异 | 保证现场可演示，发现版本和状态关联错误 | 一段真实录屏及最终提交记录；仅失败步骤修复后重查 |
| T2 创新验证 | 逐项检查 3 个演示案例及 3 个变式的诊断依据、提示层级和复测状态；其中 2 例与同模型同代码的普通助手做精简对照 | 确认新增机制真实工作，避免只适配一段固定代码 | 一页 6 行案例记录，2 组原始响应对照；失败和改动保留 |
| T3 关键修复 | 针对实际修复检查宿主文件/网络隔离、资源超限与任务回收、安全渲染、大整数判题、提交归属，以及超时/重试不丢代码；各用最小针对性输入 | 这些已知问题会破坏运行、证据或用户数据，不能用演示成功代替 | 复用现有工具或少量稳定回归；只覆盖相应故障机制，不扩展攻击/设备矩阵 |
| T4 最终交付 | 在实际展示浏览器和分辨率彩排一次；按实际交付说明在干净环境启动一次；如有数据库迁移，验证一次旧数据升级 | 确认不是只在当前开发状态下可用 | 启动步骤、环境版本、彩排记录；可与最终录屏合并 |

T2 的精简对照统一题目、代码、模型、参数和近似输出预算，普通助手不提供运行证据，改进版提供证据和学习交互。分别展示引用、提示和动作追踪上的实际差异。两例对照用于说明功能与设计差异，不据此给出总体准确率提升或学习效果结论，也不宣称其他产品没有这些能力。

验收以具体行为为准：演示引用能追溯、低层提示未直接给完整解法、未运行的代码不显示通过、错误候选修改仍会判失败、刷新能恢复记录、关键修复检查通过。可以使用明确标为测试输入的错误候选验证失败分支，不能伪造一段“AI 真实生成的错误答案”。变式失败应如实保留；修复不了就收窄能力描述，不只保留成功样例。

执行节奏：

- 开发时仅运行受本次改动影响的测试。展示文字、间距等低风险调整只做相应页面检查，不新增机械重复的单元测试。
- 沿用已有自动测试与 CI；最终集成时运行一次现有必要检查。已有失败只排查真实原因，不通过删断言或关闭 CI 制造通过。
- 不要求每轮运行全部 28 项单元/API 测试和全部浏览器冒烟测试，也不新增覆盖所有页面、题目、语言和设备的矩阵。
- 相应检查通过后即停止；只因后续相关改动、真实失败或未解决问题重跑。最终彩排同时承担演示验证，不再额外要求三次完整重复流程。
- 取消原方案的 30 例基准、三组全面评测和 80% 准确率门槛；学生试用仅在有现成参与者时收集简短反馈。本轮不新增压力测试、P95/成本统计或统计显著性分析，这些均不作为交付条件。
