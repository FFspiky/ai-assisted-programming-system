# 智练 CodeLab AIGC 参赛实施方案（修订版）

更新：2026-10-13。目标方向沿用此前选定的「AIGC 智能助手与交互体验设计」。已实施 F1 证据边界修复、F2 分级帮助及 F3 最小修改复盘；六例材料、两组对照与正式录屏仍待完成。

## 1. 定位与交付目标

完成后的作品定位：**执行证据驱动、帮助程度可控、修改过程可回看的编程学习助手。**

核心体验：错误提交 → 查看实际运行结果 → 主动选择帮助程度 → 判断与修改 → 重新判题 → 回看协作过程。

三项贡献分别是：解释与真实提交证据关联；帮助内容与学生主动选择关联；建议、修改和实际复测关联。团队贡献落在数据组织、交互规则、执行集成和过程记录，不宣称基础模型、渐进提示或 Diff 首创。

官方评分中，创新性与原创贡献 25 分、技术实现与规范 25 分、完成度与可验证性 20 分、展示与答辩 10 分。交互质量也属于创新、技术和完成度，不能把界面设计仅视为最后的包装。来源：[官方评分标准](../官方要求/附件2%202026年第十四届全国大学生数字媒体科技作品及创意竞赛评分标准及奖项设置.pdf)。

## 3. 第一优先级：补齐 F1 的证据边界

### 功能要求

1. 诊断至少区分「可提出有依据的疑似原因」「公开证据不足」「服务失败」三种结果。证据不足是正常业务结果，不能提示用户反复重试来凑出发现。
2. 支持空 findings。只有实际提出发现时才检查其代码行和引用；无法确定时不给强制行号或伪造置信度。
3. 公开用例通过、总判定失败时，保留真实失败状态，明确说明公开运行结果不足以确定根因，不把通过用例当作失败证据。
4. 若进一步提供静态代码检查方向，标为待验证推测，不声称由公开执行证实，不推断隐藏输入或答案。
5. 未执行用例不是失败证据。输入输出被截断或缺少必要内容时说明证据限制。
6. 旧诊断需要兼容展示。进入学习模式后遵循 F2 的揭示规则，不能因缓存、刷新或摘要提前展示完整分析。

### 最小完成标准

公开失败证据可以支持定位；没有足够公开证据时可以正常结束并说明限制；隐藏输入不泄露；无论能否解释，判题结果由实际执行决定。

## 4. 第二优先级：F2 统一控制帮助内容的揭示

F1 是证据基础，F2 管理信息展示。保留原有结果区，将现在一次展示原因、行号、建议的「分析错误」流程改为按需选择帮助。

| 阶段 | 展示内容 | 约束 |
| --- | --- | --- |
| 运行结果 | 判题状态、公开输入、预期/实际输出、真实运行错误 | 不自动调用模型；已有编译器或运行时错误中的行号属于事实，无需人为抹掉 |
| 概念线索 | 相关概念、观察方向、下一步自查问题 | 不增加具体修改行或完整修正答案 |
| 定位与解释 | 疑似位置、原因说明、公开证据引用 | 继承 F1 的来源和证据不足约束 |
| 局部修改 | 针对当前问题的最小建议及理由 | 绑定提交快照，查看精确 Diff 后主动采纳；不覆盖已经继续编辑的代码 |
| 完整参考解法 | 用户明确选择后给出完整候选实现 | 单独记录；未执行时显示待验证 |

### 交互与状态规则

- 可以逐级请求，也可以主动选择更高帮助程度；不强迫固定三轮对话。
- 记录「请求了哪一层、实际展示了哪一层」，不能只记录点击次数。模型无法保证绝不越级；一旦发现泄露就记录问题、修复提示或收窄能力表述。
- 当前层级、已读内容和证据状态清楚可见；刷新恢复已选择的状态，不把未选择的内容展开。
- 摘要、标题、默认高亮、旧缓存和模型思考展示都不能绕过帮助控制。学习模式中不展示可能提前暴露答案的原始思考内容。
- 后端按账号、题目、提交记录模式与帮助状态，校验请求；不能只靠前端隐藏按钮。
- 换题、换语言、新提交或代码已改动时，不能静默沿用不匹配的建议。已读内容保留所属提交标识。

### 其他 AI 入口

| 入口 | 学习模式 | 自由辅助模式 |
| --- | --- | --- |
| 普通聊天 | 独立于学习模式，正常对话与完整代码帮助；题目上下文始终手动附带 | 同左 |
| 附带当前练习 | 始终由用户主动点击；显示附带状态、支持取消 | 同样主动附带 |
| AI 优化 | 先提供分析或局部修改；完整候选需明确选择 | 保留 0–3 个必要版本，不强凑数量 |
| 自动补全 | 关闭，前后端同时约束 | 主动切换自由辅助后开启；切回学习模式关闭并清除缓存 |
| 完整参考解法 | 有直接入口，不禁止；记录实际展示动作 | 可正常请求 |

学习模式用于控制系统内的帮助行为，不宣称防止了外部求助或证明学生独立完成。用户明确索要完整代码时给予可见选择，不暗中输出也不无休止拒绝。模式由后端核验；提示词只承担内容约束，不能作为唯一控制手段。

### 最小完成标准

同一次提交存在实质不同的概念、定位、局部修改内容；默认结果不提前揭示完整分析；其他入口遵循选择的模式；能够恢复帮助状态；普通聊天仍保持手动附带上下文。

## 5. 第三优先级：F3 最小完整协作复盘

范围固定为：**局部 Diff、采纳/拒绝、撤销、真实复测、刷新回看。** 在现有结果区使用可展开区域，不另建大型协作平台或独立宣传页。

### 主流程

1. 建议绑定生成时的代码快照，生成局部差异预览。
2. 学生选择采纳或拒绝。采纳前确认当前代码与建议基础版本一致；不一致时提示重新生成或手动合并，禁止覆盖后续编辑。
3. 采纳后标记待验证。提供撤销；若学生已继续编辑，不能用旧快照直接覆盖新改动，须提示差异或提供安全的恢复选择。
4. 使用现有执行器重新提交判题，并把结果关联到实际执行的代码版本。
5. 在结果区回看提交、帮助选择、建议、采纳/拒绝/撤销、后续编辑与复测事件。
6. 刷新后恢复已保存过程，所有记录只对所属账号开放。

### 状态表达

- 未运行的建议只能标为待验证。
- 复测失败显示真实失败结果，可以继续修改。
- 复测通过显示「该次提交通过当前 N 个用例」，不能宣称普遍正确。
- 采纳后继续编辑再通过，应显示这一过程，不能把最终成功全部归因于原建议。
- 采纳和通过均不等于理解或掌握，不自动生成此类评价。
- 人工修改可记录已观察到的快照差异，不推断学生思考或外部工具使用。

### 最小记录与可靠性

沿用 Submission，补充帮助记录、建议记录及必要事件：所属账号/题目/提交、模式、请求/展示层级、提示词版本、请求模型标识及必要参数、建议基础快照、候选修改、用户动作、后续提交 ID、时间。服务端返回的模型标识如实际可获取则另存，不能将配置标识写成已独立验证的真实型号。

记录保存失败时明确提示未保存，不能伪装为可恢复。避免为上述流程建设完整 StudySession、推荐画像、复杂事件平台或每次键盘输入的全量追踪。

### 最小完成标准

能准确回答：建议基于哪份代码、用户做了什么、最后实际运行了哪份代码、结果是什么。应用和撤销不覆盖后续编辑；刷新后关联保持正确。

## 6. 界面原则与演示设计

- 沿用现有颜色、字体、按钮、题目—编辑器—结果结构。
- 不恢复宣传横幅、独立诊断右栏、进入演示按钮、载入错误示例或题面 AI 说明。
- 帮助选择放在运行结果附近；局部 Diff 和时间线按需展开。
- 核心状态使用短文案，避免界面出现模型版本、提示词版本、内部记录 ID 等无助于用户决策的说明。
- 桌面投屏优先，同时检查本次新增控件在窄屏可读可操作；不开展全站换肤和全面移动端重做。
- 个人页、角色形象、窗口交互等既有功能保留，后续优先解决阻断核心操作的问题，不扩张为新功能主线。

内部四分钟演示目标（正式时长按提交要求）：

| 时间 | 实际操作 |
| --- | --- |
| 0:00–0:20 | 用一句话说明初学者需要理解错误和控制帮助，进入普通刷题页 |
| 0:20–1:00 | 提交错误代码，查看真实输入输出差异 |
| 1:00–1:50 | 主动选择概念线索，再请求定位并查看依据 |
| 1:50–2:50 | 查看局部 Diff，选择处理建议，修改后真实复测 |
| 2:50–3:20 | 回看帮助、修改和复测的记录 |
| 3:20–4:00 | 展示证据不足/复测失败的短例及同信息对照，说明团队贡献 |

不把历史录屏伪装成实时结果。网络异常时，备用回放须明确日期与来源。三张材料图围绕证据定位、帮助选择、修改差异与复测关联制作。

## 7. 六个案例与两组对照

保持总共六个代表案例，新增的特殊分支纳入三个变式，不另扩展大评测集。

| 案例 | 场景 | 验证重点 |
| --- | --- | --- |
| A1 | 循环边界（已有） | 真实失败证据、按需帮助、局部修改与复测闭环 |
| A2 | 字符串索引（已有） | 运行错误与行号、证据关系 |
| A3 | 输入类型（已有） | 输出错误与类型推断的界限，避免重复根因 |
| V1 | 改变循环结构或错误条件 | 不能仅记住固定 range 写法、数字或行号 |
| V2 | 示例通过、合法边界下隐藏用例失败 | 正常返回证据不足，不泄露隐藏内容、不强行定位 |
| V3 | 多处或分支相关问题，第一次候选只修复一部分 | 真实复测仍失败，继续修改与记录关联正确 |

V1–V3 在提示设计稳定后冻结输入与预期，再检查；须有结构或条件变化。具体代码与边界以题目允许范围为准，预期由参考实现和人工检查确认。失败案例保留，不靠换掉样例取得全部通过。

V3 优先保留真实模型的不充分建议；如果没有这种自然输出，可以使用明确标为「人工构造的错误候选」验证失败分支，不冒充 AI 原始回复，也不反复消耗 API 去追求一次失败。

| 对照 | 固定条件与差异 | 允许得出的结论 |
| --- | --- | --- |
| 证据作用对照 | 同模型、题目、代码及相近参数/预算；一组增加公开执行证据 | 说明证据输入怎样影响这两个具体回复，不归因为纯交互提升 |
| 交互作用对照 | 同模型、相同题目/代码/公开证据及相近参数/预算；普通助手也给予合理的按需提示要求 | 比较引用追溯、帮助选择、差异核对、复测和回看如何完成；不故意弱化普通助手 |

两组各复用已有案例。保留原始响应、输入、参数与操作步骤；不声称一次样例证明稳定优越、全题库准确率或学习效果。若测量时间或操作次数，必须实际记录，不能根据界面推算。

## 8. 仅保留必要验证

| 阶段 | 必要检查 | 停止条件 |
| --- | --- | --- |
| 诊断边界 | 公开失败可分析；公开证据不足正常结束；隐藏内容不泄露；空发现结构合法 | 分支与界面状态一致 |
| F2 | 层级内容有差异；不能通过摘要/思考/刷新泄露更高层；跨入口模式与主动附带规则有效 | 代表流程和受影响入口通过 |
| F3 | 采纳/拒绝/撤销；编辑冲突；失败与通过的真实复测；账号归属和刷新恢复 | 建议、代码和提交对应正确 |
| 集成交付 | 一次完整流程，复用六例差异检查和两组对照；实际展示环境彩排；按说明在干净环境启动；有迁移则备份并验旧库 | 核心流程可演示，材料与实现相符 |

- 开发时用模拟模型响应检查状态、引用和数据流；内容分级及两组对照需要少量真实模型响应确认，不能全靠模拟验收。
- 已通过的执行隔离、渲染、判题检查只在相关逻辑被改动、发生失败或存在未解问题时重跑。
- 低风险文字和样式调整做页面检查，不新增镜像实现的单元测试。
- 沿用已有 CI；最终集成做一次相关检查，不反复跑全套、不删失败断言制造通过。
- 不新增30例基准、压力测试、设备矩阵或统计显著性分析；不设无样本依据的总体准确率门槛。
- 有现成同学时，可观察能否解释修改理由及独立完成相似变式，记录为探索性反馈，不作为交付前置或普遍教学收益证据。

## 9. 实施顺序与范围冻结

| 顺序 | 交付物 | 进入下一步的条件 |
| --- | --- | --- |
| 1 | 正常工作的证据不足状态 | 不强制编造发现，真实判题和数据边界保持正确 |
| 2 | 一次提交的帮助控制与已有 AI 入口联动 | 已实现实质不同的帮助层级和主动选择，刷新无意外揭示 |
| 3 | 局部 Diff、操作和复测回顾 | 版本关联、撤销、失败结果和恢复可靠 |
| 4 | 六例记录、两组对照、可录制版本 | 失败如实保留，已知核心阻断问题解决 |
| 5 | 录屏、说明、PPT和运行包 | 材料与实际成果一致，按说明可启动 |

按依赖推进，不把旧排期日期当成完成承诺；正式提交时间仍以实际平台和学校安排为准。功能开发中同步保留截图与记录，最终彩排兼作录屏验证。

后置：自动推荐、高级题库筛选、长期报告、问卷重设计、时长与积分全面治理、成本看板、更多语言、复杂编辑器、全面移动端改造、导出和额外动效。自训模型、多智能体、知识图谱不进入本轮。
