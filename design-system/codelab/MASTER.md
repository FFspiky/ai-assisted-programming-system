# CodeLab 界面规范

2026-10-15。适用于现有页面的细节精修及 AI 共创新页面。

## 不变的品牌与约束

- 保留深海蓝底色、浅蓝强调色、半透明蓝色面板及原有中文系统字体。
- 达菲郁是产品角色：保留首页形象、刷题页桌宠、动作菜单、拖动和聊天。新页继续使用已有本地素材。
- 精修信息层级、间距、可读性和操作反馈，不更换整个视觉体系。
- 原首页交互演示继续标注示例；真实功能由明确入口进入。

## 来源与取舍

已使用 `ui-ux-pro-max` 的设计系统检索及 `form error recovery focus` UX 检索。教育产品结果包含偏儿童的字体与新色板，与本项目现有大学生学习场景、用户要求不符，未采用或原样持久化。

采用经核对适用的清晰层级、可见焦点、提交反馈、错误恢复和适度动效指导。最终色彩与字体来自项目现有 `static/css/ocean-theme.css`，以用户保留原风格的要求为准。项目栈为 Flask/Jinja、原生 CSS 与 JavaScript；不套用 React 或 Tailwind 的实现规范。

## 基础令牌

| 用途 | 现有值 |
|---|---|
| 页面背景 | `--darker: #0d1b2d` |
| 常规面板 | `--ocean-panel: #172c44` |
| 抬升面板 | `--ocean-raised: #213a56` |
| 代码区 | `--code-bg: #101f32` |
| 正文 | `--light: #f2f7fd` |
| 次级正文 | `--gray: #b1c3d8` |
| 强调 | `--accent: #a5c9ff` |
| 成功／待定／错误 | 现有 `--success`、`--warning`、`--danger` |

间距以 4、8、12、16、24、32、48 px 形成节奏。正文默认 15～16 px，行高约 1.6；辅助说明保持可读，不用密集的小字承载关键操作。

## 页面与组件

- 主导航按首页、刷题、AI 共创、实战任务室、学习分析排列；当前项明确。小屏可换行，账号和导航均保持可用。
- 标题先说明这一步要完成什么；主操作每个区域不超过一个，次操作保持明显的视觉次序。
- AI 共创以例子、候选和真实差异为中心。两候选桌面并排、小屏竖排；代码块内部可横向滚动，页面本身不能溢出。
- 通过、失败、未运行、生成失败、来源均有文字标记，不能只靠颜色。
- 空状态给出下一步操作；生成或执行失败保留已填写内容，并提供明确重试。
- 耗时请求立即显示进行中状态，防重复点击。取消等待不能声称服务端任务已经终止。

## 交互与可访问性

- 所有输入有可见标签；错误使用 `role=alert` 或适当 live region。
- 主操作触控目标至少 44 px；保留清晰的 `:focus-visible`。
- 候选解释和模型内容以安全文本渲染；不用生成内容插入 HTML。
- 动效优先 opacity/transform，约 150～250 ms；尊重 `prefers-reduced-motion`。
- 宠物、聊天窗口及代码编辑器有自己的交互约束，公共细节样式不得覆盖透明编辑层或改变桌宠行为。
- 装饰图标有相邻文本时从可访问树隐藏；图标按钮有明确名称。

## 验收范围

- 375/390 px 与桌面宽度：导航、表单、候选、错误提示无页面横向溢出。
- 键盘可到达主要操作，焦点不会被宠物或浮层遮挡。
- 访客能浏览，登录后才能保存或调用 AI/执行。
- AI 真实生成与教学样例分开显示，已测试范围清楚；候选代码未运行时不显示已验证。
- 原刷题页的桌宠、动作菜单与聊天仍能工作。

## 2026-10-16 题目共创与多语言

共创围绕题库题目展开，做题页只提供轻入口，独立工作台承接题意、公开样例、语言与代码；保留原海洋蓝令牌及达菲郁互动。Python、C++、Java 按题目分别保存草稿；候选回填前显示差异，用户主动采纳并可撤回。错误/超时保留输入，不将用户期望、参考程序输出或相同输出等同于正式判题通过。隐藏用例不向页面、模型或导出开放。

## 2026-10-18 学习共创三阶段

沿用现有风格，增加可自由返回的“验证 AI 代码、解释修改、独立再做一次”阶段导航。学生解释只由本人填写，保存绑定具体代码；旧解释及其证据作为历史呈现。复盘卡独立展示真实过程，可导出，空状态明确留空。独立练习保留达菲郁和编辑器，暂时收起本页 AI 帮助，退出后恢复原辅助偏好；若已有草稿或提交，说明并保留起点。阶段状态描述已发生的操作，不使用掌握百分比或虚构学习结论。

### 前端精修约定

- 三阶段导航放在标题后。选题、筛选和新建收在可展开的当前题目摘要中；内部共创方式用文字分段切换，避免重复编号。
- 共创页正文与表单使用 14～15 px，普通说明 13 px，元信息至少 12 px，代码 13 px。解释文本采用系统字体，与代码的等宽字体区分。样式限定在 `.problem-create-page`，避免影响原刷题编辑器的透明输入层。
- 保存反馈持续区分账户记录版本、本机草稿、未提交修改和本机保存失败。较早版本的本机输入保留；有未保存修改时要求核对最新记录，表单与账户一致时不额外锁定。
- 达菲郁桌面侧栏保留；窄屏在阶段附近提供可展开的陪伴条，使用同一条本地提示，无需模型请求，不遮挡输入。
- 代码候选头部呈现来源与公开样例结果，实际输出和对照输出标清依据；补充测试及实现说明可展开。选择、验证和带回仍是独立的主动操作。
- 复盘先给实际运行、本人解释、关联题正式提交三个事实摘要，再给下一步和证据明细；空白、过期和记录不可用须明确展示。
- 独立练习顶部采用紧凑任务条，约束说明展开查看，已有草稿提示仍可见。帮助自述位于实际提交结果之后；重新进入可恢复本次尝试已关联的提交，新的提交默认重新留空自述。
